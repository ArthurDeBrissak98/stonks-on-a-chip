# ADR-001: Выбор MCU для tick-to-trade стенда

- **Статус:** Accepted
- **Дата:** 2026-11-11
- **Контекст проекта:** stonks-on-a-chip v2 (перезапуск с нуля)
- **Заменяет:** неформальный выбор STM32F4 в v1 (v1 архивирован)
- **Связанные документы:** [ADR-002 — стратегия транспорта](ADR-002-transport-strategy.md), [LIMITS-EXPERIMENT-PLAN](LIMITS-EXPERIMENT-PLAN.md)

---

## 1. Контекст

v1 проекта был образовательной песочницей: UART + WebSocket + QEMU. Такой стек
не позволяет измерять ничего физически интересного — узким местом был транспорт,
а не кремний.

v2 ставит другую цель: **найти физические пределы MCU** для задачи
tick-to-trade, прежде чем переходить на следующий уровень абстракции
(Ethernet, kernel bypass, FPGA). Это значит, что платформа обязана уметь:

1. **Точно измерять время.** Нужен аппаратный счётчик циклов с наносекундным
   разрешением — то есть `DWT->CYCCNT` (Data Watchpoint and Trace unit), а не
   `k_cycle_get_32()` поверх таймера.
2. **Убирать память из уравнения.** Чтобы измерять CPU и транспорт, а не
   промахи кэша, нужна память с детерминированной латентностью — TCM
   (Tightly Coupled Memory). Отсутствие TCM означает, что джиттер измерения
   определяется арбитражем шины, и «предел» измерить нельзя.
3. **Иметь кэш как объект исследования.** Кэш — не только ускоритель, но и
   источник худшего случая латентности. Он должен быть управляемым (включаемым/
   выключаемым, с возможностью закрепления регионов через MPU).
4. **Запускать RTOS с предсказуемым планировщиком.** Zephyr — выбранная ОС;
   нужна поддерживаемая (Maintained) board-цель, а не «собранный кем-то форк».
5. **Иметь достаточный запас по частоте**, чтобы 550 MHz было достижимо
   штатно (не в режиме оверклока за пределами спецификации).
6. **Стоить как инструмент, а не как проект.** Целевой бюджет платы — до ~$150,
   чтобы заказ и ошибка в выборе не были болезненными.

### Критерии сравнения

| Критерий | Почему важен для v2 |
|---|---|
| Максимальная частота | Разрешение DWT и запас по бюджету циклов на тик |
| TCM (ITCM/DTCM) | Детерминированная латентность кода и данных |
| L1 I/D-кэш | Исследование кэша как источника джиттера |
| DWT resolution | Разрешение измерения (1 / f_cpu) |
| Статус Zephyr | «Maintained» = есть CI, ревью и обновления |
| Сложность toolchain | Время до первого замера, стоимость входа |
| Цена | Стоимость ошибки выбора |

## 2. Рассмотренные варианты

1. **STM32F4** — базовая линия v1 (представитель: STM32F446RE).
2. **STM32F7** — M7 без серьёзного роста частоты (представитель: STM32F767ZI).
3. **STM32H7** — M7 @ 550 MHz с полноценными TCM и кэшами (представитель:
   STM32H723ZG).
4. **i.MX RT1170** — 1 GHz M7 + 400 MHz M4, самый быстрый вариант.
5. **Renesas RA8** — Cortex-M85 @ 480 MHz (представитель: RA8M1).

## 3. Решение

**Принят STM32H723ZG в виде платы NUCLEO-H723ZG.**

---

## 4. Обоснование

- **550 MHz** — даёт разрешение DWT **1.82 нс** и максимальный бюджет циклов
  на тик среди рассмотренных вариантов с полноценными TCM.
- **64 KB ITCM + 128 KB DTCM** — достаточно, чтобы целиком разместить горячий
  путь (обработчик тика + стратегия + буферы) в памяти без кэша. Это ключевое
  требование: без TCM «предел» измеряемой системы определялся бы кэшем, а не
  CPU.
- **32 KB L1 I/D-кэш** (16 + 16) — есть что включать, выключать и промахивать;
  кэш становится управляемой переменной эксперимента, а не фоном.
- **DWT resolution 1.82 нс** — цена деления почти в 3 раза лучше, чем у F4
  (5.56 нс), что позволяет измерять джиттер, не утонув в квантовании.
- **Цена ~$30–35** — в 4–5 раз дешевле RT1170 и RA8. При равном бюджете это
  позволяет купить запасную плату (риск «окирпичивания» и параллельные замеры).
- **Полная поддержка Zephyr: board `nucleo_h723zg`, статус Maintained [V]** —
  нет необходимости поддерживать собственный BSP. ST-LINK/V3 уже на плате:
  отдельный программатор не нужен.
- **Ethernet на плате** — путь развития из ADR-002 (SPI → Ethernet) не требует
  смены железа, только нового драйвера.

### Почему не остальные

| Вариант | Причина отказа |
|---|---|
| **STM32F4** | Нет TCM и нет L1-кэша → нельзя отделить CPU от памяти. Частота 180 MHz даёт 5.56 нс и ~23.9 с до переполнения DWT. Это уровень v1, а не v2. |
| **STM32F7** | Тот же M7, но 216 MHz и TCM всего 16/64 KB. Прирост над F4 не оправдывает шаг: 4.63 нс разрешение и 16 KB ITCM — тесно для горячего пути. |
| **i.MX RT1170** | Формально быстрее (1 GHz, 1.00 нс, 512 KB TCM), но: dual-core (два образа, межъядерная синхронизация — лишняя переменная на старте), загрузка через DCD/FCB и внешняя память, toolchain заметно тяжелее, цена в 4–5 раз выше. Сложность не окупается на этапе «найти пределы одного ядра». |
| **Renesas RA8** | Cortex-M85 и TrustZone интересны, но семейство молодое: поддержка Zephyr тоньше, toolchain (FSP/e² studio) менее привычен, а в DT нет привычных ITCM/DTCM-узлов — то есть модель памяти не подтверждена на уровне BSP. Для задачи «измерить предел» нужна предсказуемость, а не новизна ядра. |

## 5. Последствия

Обязательства, которые принимаются вместе с решением:

- [ ] **Переписать linker script** — разместить код горячего пути в ITCM, а
      данные (буферы тиков, состояние стратегии, стек главного потока) в DTCM.
      Штатный скрипт Zephyr кладёт всё во flash/SRAM; нужны секции
      `.itcm.text` / `.dtcm.data` и, при необходимости, MPU-регионы.
- [ ] **Учесть переполнение `DWT->CYCCNT`.** Счётчик 32-битный и при 550 MHz
      переполняется примерно **каждые 7.81 с**:
      `2^32 / 550 000 000 ≈ 7.809 с`.
      Любой тест длиннее ~7.8 с обязан вести overflow-учёт (см. §«Обработка
      переполнения DWT» в [LIMITS-EXPERIMENT-PLAN.md](LIMITS-EXPERIMENT-PLAN.md)).
      Для Раздела 5 плана (джиттер под нагрузкой, длительные прогоны) это
      критично: наивный `t_end - t_start` даст мусор.
- [ ] **Заложить время на отладку драйверов Zephyr для H7.** Драйверы H7 в
      Zephyr моложе и менее обкатаны, чем F4. Ожидаемые точки трения: SPI/DMA
      (FIFO, `fifo-max-transfer-size`), кэш-когерентность при DMA, clock
      tree (домены D1/D2/D3, `st,stm32h7-pll-clock`). Закладываем буфер
      времени в план, а не «допишем по ходу».
- [ ] **Купить плату.** NUCLEO-H723ZG, ~$30–35. Пока плата не куплена,
      статус проекта — Planning phase (см. [README](../README.md)).
- [ ] **Подтвердить объём L1-кэша** по даташиту STM32H723ZG перед Разделом 4
      плана и заменить пометку [~] в таблице выше на точное значение.

## 6. Источники и как проверялись цифры

Цифры, помеченные [V] в таблице, взяты из:

- **Zephyr board doc `nucleo_h723zg`** — статус `Maintained`, SoC
  `stm32h723xx`, 550 MHz, 1 MB Flash, 562 kB SRAM max (320 KB на таргете),
  Ethernet, high-resolution timer 2.1 ns.
  <https://docs.zephyrproject.org/latest/boards/st/nucleo_h723zg/doc/index.html>
- **Zephyr devicetree `dts/arm/st/h7/stm32h7.dtsi`** — `itcm` 64 KB @ `0x00000000`,
  `dtcm` 128 KB @ `0x20000000`.
- **Zephyr devicetree `dts/arm/st/h7/stm32h723.dtsi`** — `sram0` 320 KB
  @ `0x24000000`, состав доменов SRAM.
- **Zephyr board doc `mimxrt1170_evk`** — `Maintained`, M7 @ 1 GHz + M4 @ 400 MHz,
  2 MB SRAM, 512 KB TCM для M7 и 256 KB для M4.
- **Zephyr devicetree `dts/arm/nxp/imxrt/imxrt11xx/nxp_rt11xx_cm7.dtsi`** —
  `itcm` 256 KB, `dtcm` 256 KB.
- **Zephyr board doc `ek_ra8m1`** — `Maintained`, Cortex-M85 @ 480 MHz,
  896 KiB RAM, 2016 KiB Flash.
- **Zephyr devicetree `dts/arm/renesas/ra/ra8/ra8x1.dtsi`** — `sram0` 896 KB
  @ `0x22000000`.
- **Zephyr devicetree `r7fa8m1xh.dtsi`** — `cpuclk` = 480 MHz.
- **Zephyr board doc `nucleo_f767zi`** — `Maintained`, 216 MHz, 512 KB SRAM,
  2 MB Flash.
- **Zephyr devicetree `dts/arm/st/f7/stm32f7.dtsi`** — отсутствие
  TCM/кэш-узлов (кэш и TCM в DT не описываются).
- **STMicroelectronics CMSIS device header `stm32h723xx.h`** — `__ICACHE_PRESENT`
  и `__DCACHE_PRESENT` = 1, `__CM7_REV = 0x0110` (Cortex-M7 r1p2),
  `__NVIC_PRIO_BITS = 4`.

Производные величины рассчитаны, а не взяты из документации:

- DWT resolution = `1 / f_cpu`: 550 MHz → 1.818 нс; 480 MHz → 2.083 нс;
  216 MHz → 4.630 нс; 180 MHz → 5.556 нс; 1 GHz → 1.000 нс.
- DWT CYCCNT overflow = `2^32 / f_cpu`: 550 MHz → 7.809 с; 480 MHz → 8.948 с;
  216 MHz → 19.884 с; 180 MHz → 23.861 с; 1 GHz → 4.295 с.

Проверка при закупке: сверить партномер платы (`NUCLEO-H723ZG`), объём
L1-кэша и наличие RMII-физики по даташиту и board manual.
